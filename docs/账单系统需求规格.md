# 账单系统 需求规格说明书 v1

> 基于 new-api（https://github.com/QuantumNous/new-api ）多站点架构的成本对账与客户利润核算系统。
> 本文为定稿前的需求规格，作为后续数据库设计、接口设计与开发的依据。

---

## 1. 项目背景与架构

### 1.1 现有架构
- **总站**：运行 new-api，创建多个**分组(group)**，从各供应商/第三方代理接入资源，配置为**渠道(channel)**。总站对外统一按 **1 倍率**计费消耗，再从不同分组创建**令牌(token)**分配到客户站点。
- **供应商**：大部分同样使用 new-api 开源项目；总站渠道的 sk 即供应商侧的某个 key/令牌。
- **客户站点**：独立运行 new-api。站内**渠道**的 sk = 总站的某个**令牌**；每个分组对应一个渠道；客户选择分组即命中总站对应分组。

### 1.2 账单系统两大模块
1. **成本侧**：总站 ↔ 供应商对账（核算真实进货成本）。
2. **收入侧**：客户站点实际成本与利润核算（客户成本依赖总站供应商成本）。

## 2. 技术栈与部署（已定）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python + FastAPI | 适配器/爬取/调度生态成熟 |
| 数据访问 | SQLAlchemy | 统一只读直连混合数据库(MySQL/PG/SQLite) |
| 账单自有库 | PostgreSQL（独立） | 与被读源库隔离，强一致、利于聚合校验 |
| 调度 | APScheduler（可升级 Celery+Redis） | 凌晨任务链、可配 cron、限速分批 |
| 凭据加密 | AES/Fernet（密钥走环境变量） | 供应商账密安全存储 |
| 前端 | React + Semi Design | 与 new-api 同款 UI，差异颜色/表格好实现 |

**部署形态**：独立系统，与 new-api 解耦。
**数据获取**：**只读直连**总站/客户站点数据库；低峰执行、限速、分批读取，**严禁影响主业务**。
**币种**：统一 **人民币 RMB**。

## 3. 核心计算公式（定稿）

| 项 | 公式 |
|---|---|
| 渠道消耗量口径 | 总站 `logs.quota`（总站 1 倍率，即基准量） |
| 总站渠道理论成本 | Σ(按量模型 消耗量 × 渠道消耗倍率) + Σ(按次模型 单次价格 × **成功调用次数**) |
| 供应商实际成本 | 平台查询消耗(RMB) × 充值倍率 |
| 对账差异额 | 理论成本 − 实际成本 |
| 对账差异% | 差异额 ÷ **供应商实际成本** |
| 分组总成本（核算基准） | **对账确认后的供应商实际成本** 汇总到分组 = 供应商按量部分成本 + 供应商按次部分成本 |
| 令牌实际成本 | 分组总成本 × **令牌总站 quota 占比**（令牌总站消耗 ÷ 分组总站消耗）。总站对外按量，**单一占比，不区分供应商按量/按次** |
| 令牌成本按模型拆分 | 令牌内某模型成本 = 令牌实际成本 × (该模型总站 quota ÷ 令牌总站 quota) |
| 客户分组成本 | Σ_模型 [ 该模型令牌成本 × 客户在该模型的占比 ]；占比度量由**客户站该模型计费方式**决定：按量→1倍率消耗(quota)占比，按次→成功调用次数占比 |
| 客户营收 | 客户当天**实际扣除额度** 折算为 RMB（客户站额度本身按人民币设定，按站点 QuotaPerUnit 折算，比例可配，默认 1 显示单位=1 元） |
| 利润 | 客户营收 − 客户分组成本 |
| 毛利率 | 利润 ÷ **客户营收** |

> **三个计费视角相互独立**：①总站对外计费（统一按量1倍率）②供应商对我计费（按量/按次混合，仅用于算分组总成本）③客户站对客户计费（按量/按次，决定客户占比度量）。
> **令牌占比**永远用总站 quota 消耗比例；**客户占比**用客户站该模型计费方式对应的度量。供应商侧的按量/按次分类**不参与任何占比**，只影响分组总成本。
> 供应商查询消耗单位统一视为 RMB，币种换算由"充值倍率"承担，系统不做汇率换算。

## 4. 数据模型（账单库实体草案）

| 实体 | 关键字段 |
|---|---|
| `site` 站点 | id、类型(总站/客户站)、名称、只读DB连接信息、`track_customers`(是否核算客户)、QuotaPerUnit(额度→RMB折算比例，默认1显示单位=1元) |
| `supplier` 供应商 | 名称、平台类型(newapi/其他)、站点URL、采集方式 |
| `supplier_credential` 凭据 | supplier_id、加密账密/cookie/token、过期时间、状态 |
| `channel_map` 渠道映射 | 总站 channel_id、supplier_id、sk、是否多渠道共用 sk |
| `channel_ratio` 渠道消耗倍率 | channel_id/sk、倍率、生效起始日（历史版本） |
| `recharge_ratio` 充值倍率 | supplier_id、倍率(默认1)、生效起始日（历史版本） |
| `per_call_price` 按次价格 | channel_id+model、单次价格、生效起始日（历史版本） |
| `customer_billing_mode` 客户站计费方式 | site + (group/channel) + model、计费方式(按量/按次)，决定客户占比度量 |
| `daily_channel_usage` 渠道日消耗 | 日期、channel_id、model、计费类型、消耗量、成功次数、理论成本 |
| `daily_supplier_cost` 供应商日成本 | 日期、supplier_id、sk、平台消耗(RMB)、实际成本、采集状态 |
| `reconciliation` 对账单 | 日期、sk(合并)、理论成本、实际成本、差异额、差异%、状态(草稿/已确认/已锁定) |
| `group_cost` 分组成本 | 日期、group、按量成本、按次成本、总成本 |
| `token_cost` 令牌成本 | 日期、token、总站quota占比、实际总成本（单一成本，不再拆按量/按次） |
| `customer_group_usage` 客户分组消耗 | 日期、site、customer、group、按量quota、成功次数、按量占比、按次占比 |
| `customer_bill` 客户账单 | 日期、site、customer、group、成本、营收、利润、毛利率、确认状态 |
| `recon_job` 对账任务 | 类型(自动/手动时间段)、起止日期、状态、执行日志 |
| `audit_log` 审计 | 操作人、对象、动作(确认/解锁/改倍率/重算)、前后值、时间 |
| `app_config` 配置 | 对账cron、限速参数、差异颜色阈值、低峰时段等 |

## 6. 自动任务链与人工确认流程

```
1) 拉取前一自然日(Asia/Shanghai) 总站 logs → daily_channel_usage（理论成本）
2) 生成有消耗的 sk 采集清单 → 登录/采集供应商 → daily_supplier_cost（实际成本，已乘充值倍率）
3) 按 sk 合并 → reconciliation（差异额/%/颜色）        ←—— 停在「待人工确认」
4) 拉取客户站点 logs → customer_group_usage（占比）+ 营收（实际扣除额度）
   ——— 人工确认对账（可重对账/调倍率）———►
5) 分组总成本 → 令牌成本（总站 quota 占比）→ 客户成本（客户站计费方式占比）→ 利润/毛利率 → customer_bill 落库
```

- 第 3、4 步自动完成后停住；**人工确认后**才执行第 5 步并正式落库。
- 支持指定时间段手动重跑（测试/补账）；调整倍率后可重对账。
- 确认后允许解锁重算，但需记录审计日志。

## 8. 关键设计决策与假设（可调整）

1. **消耗量口径**：取总站 `logs.quota`（总站 1 倍率即基准量）。
2. **三个计费视角独立**：①总站对外统一按量1倍率；②供应商对我按量/按次混合——仅用于算分组总成本；③客户站对客户按量/按次——决定客户占比度量。
   - **令牌实际成本** = 分组总成本 × 令牌总站 quota 占比（单一口径，不拆按量/按次）。
   - **客户分组成本（混合兼容）**：先把令牌实际成本按"总站各模型 quota 占比"拆到每个模型；每个模型内再按客户站该模型计费方式分摊给客户（按量→quota 占比 / 按次→成功次数占比）；最后按客户汇总。
   - **客户站每模型计费方式**：在账单系统内**手动配置**(`customer_billing_mode`)，不自动读取客户站。
3. **币种**：供应商消耗统一按 RMB 处理，币种差异并入"充值倍率"，系统不做汇率换算。
4. **营收**：客户站额度本身按人民币设定，营收 = 客户当天实际扣除额度按站点 QuotaPerUnit 折算为 RMB（比例可配，默认 1 显示单位=1 元），无需充值汇率换算。
5. **令牌↔客户站**：一个总站令牌仅分配到一个客户站；供应商侧一个 sk 可被多个总站渠道共用（对账按 sk 合并）。
6. **时区**：统计"前一自然日"按 Asia/Shanghai。
7. **按次调用次数**：仅统计成功/有效请求。

8. **客户成本混合兼容**：同一分组多模型且计费方式不同时，令牌成本先按总站各模型 quota 占比拆到模型，再各模型内按客户站计费方式分摊给客户，最后汇总。
9. **客户站计费方式来源**：在账单系统手动配置（`customer_billing_mode`，每站每模型）。

> 待补充确认：供应商非 new-api 类型的具体平台清单与采集方式（遇到时再补充）。

## 9. 开发里程碑（建议）

1. **M0 基础**：账单库建模 + 站点/供应商/映射/倍率配置 + 只读连接框架。
2. **M1 + M2**：总站消耗统计 + 供应商采集（先做 new-api 适配器）。
3. **M3**：对账与差异可视化、重对账、人工确认。
4. **M4 + M5**：分组/令牌成本 → 客户成本 → 利润核算。
5. **M6**：调度任务链、指定时间段、周/月统计、审计。
6. **M7**：Web 后台完善与报表导出。
